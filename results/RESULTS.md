# Results

Generated by `griff report` from `results/results.json`. Do not edit by hand -- CI regenerates this file and fails on a diff.

Every policy meets the same episode seeds, so comparisons within a task are paired. Rates carry 95% Wilson intervals. **Peak force is read from the simulator's ground-truth F/T sensor**, not from the servo-load estimate the policy and the controller actually run on -- grading a safety property with the same noisy signal the system used to try to satisfy it would let estimator error hide the failures being looked for.

## Scoring

**Task success** is the task's own criterion: peg inserted, plate wiped end to end, part seated. **Force-aware success** additionally requires that peak contact force stayed below the threshold at which the workpiece is considered damaged. A run that completes the task by crushing the part counts as a failure, because on real hardware it is one.

| task       | overload threshold | controller limit | goal                                          |
|------------|--------------------|------------------|-----------------------------------------------|
| peg_insert | 8 N                | 6 N              | Insert the peg into the hole                  |
| wipe       | 10 N               | 7 N              | Wipe the surface of the plate end to end      |
| press_fit  | 14 N               | 12 N             | Press the part into the socket until it seats |

## Reproducing

```console
$ griff reproduce
```

Or the steps separately: `griff calibrate`, `griff record`, `griff train-grid`, `griff evaluate`. Episode seeds are fixed and committed; the datasets, configs and seeds needed to reproduce every number here are in the repository.
